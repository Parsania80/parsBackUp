# H02 configuration, access and report increment

Contract recorded before implementation on 2026-11-15. Implements the first increment of [H01](h01-production-policy.md); it does not close H02 or enable production. Legacy unversioned fixture configuration and successful bare JSON shapes remain compatible. Artifact, inventory, restore/deletion plan and crypto bytes do not change.

Follow-up on 2026-11-15: the [native authentication and maintenance recovery increment](h02-native-auth-recovery.md) supersedes the native capability refusal below for writable versioned fixture create/dry-run, live profile validation and restore plan/run. It adds fixture restore-plan v3 while preserving this increment's original v1/v2 compatibility claim. Key bootstrap, other authenticated offline reads and snapshot capabilities remain gated; production stays disabled.

Further follow-up on 2026-11-15: [validated key bootstrap and custody](h02-key-bootstrap-custody.md) supersedes the original versioned key-command refusal. Writer generate/publish and role-specific key status are delivered for fixtures; the new contract specifies protected reads, staged create-only publication and partial receipts. Snapshot and other authenticated offline backup operations remain gated. Legacy key result mappings are unchanged.

## Dispatch boundaries and alternatives

| Choice | Selected behavior and benefit | Alternative and cost |
|---|---|---|
| Versioned native execution | Refuse with `CAPABILITY_NOT_ENABLED` until the native/authentication increment implements required SCRAM and maintenance DB behavior. | Converting versioned config to legacy source wiring would silently ignore those requirements. |
| Snapshot and key custody | Refuse permitted but undelivered snapshot/key operations before opening resources. | Reusing legacy store/key constructors would load forbidden material or create locks on read-only media. |
| Legacy execution | Preserve the established fixture dispatcher; opt-in report envelope wraps its existing result values. | Duplicating native services solely for reports risks divergent behavior. |

Versioned fixture commands implemented here: `config check`, writer/reader `profile list`, and writable writer/reader/inventory keyless job/inventory commands plus protect/unprotect. These operations do not require source, tools or key files. The existing root is required for reader operations. All other policy-permitted versioned operations refuse with `CAPABILITY_NOT_ENABLED` until their owning H02 increment. In particular key generate/publish remain blocked before any key mutation; this increment makes no transactional bootstrap claim. Config checks are structural, do not open source/tools/keys/store/scratch and are not credential, deployment or artifact certification.

Authorization precedes resource opening. All roles allow config check and key status (inventory status has no material); writer/reader allow profile list. Writer alone allows create and key generate/publish. Writer/reader allow live profile validation, authenticated inspect/checksum/archive, restore and retention. Public additionally allows discovery and signature-only verification. Every role allows keyless job/inventory reads. Writer/reader/inventory allow explicit inventory maintenance and protection changes; public forbids them. Unlisted commands deny. `read_only=true` refuses any mutation or live validation with `READ_ONLY`; even read-only rebuild preview is outside the snapshot command set. Snapshot-capable commands remain unavailable in this increment rather than creating legacy lock files. A command `--read-only` flag does not override a configuration's capability ceiling. Production `--output json` refuses `OUTPUT_FORMAT_UNSUPPORTED`; otherwise every production command except config check refuses `PRODUCTION_NOT_ENABLED`, before capability-specific resources. No flag or environment variable lifts this gate.

## Configuration and file boundary

The exact version-1 fields/defaults and role custody are H01's schema. Profiles retain `[[profile]]` and the existing selection fields. Version and mode are never inferred. Unknown/duplicate/mixed fields, unsupported versions, invalid names/auth/paths and incompatible custody refuse safely. Config profile validation shares selection rules while retaining every legacy/signed-manifest fixture guard. Production data-only profiles refuse. This does not change the signed reader's accepted contract.

All configuration reads are bounded to 64 KiB and require a regular, non-symlink final file; this is an intentional input-file safety improvement on the legacy path too. Legacy relative paths and existing file permissions remain accepted. Versioned files additionally require an absolute normalized path, owner equal to the invoking service UID, mode exactly 0600 and protected no-follow ancestry owned by root/service UID without group/other writes. World-writable ancestors, including `/tmp`, refuse; examples/tests use protected directories. Descriptor traversal verifies the opened file identity. Key/passfile/tool/store/scratch descriptors and resource bounds belong to later increments; structural path checks alone do not certify them. `libc`, already locked and used throughout this Unix-only workspace, is reused by the CLI for no-follow/nonblocking descriptor flags; the only lockfile change is the CLI dependency edge, with no new package or version.

## Report v1 data and errors

`--output json-v1` emits one stdout object after argument parsing, including missing config, parse/validation/access errors and handled deletion partial results. Top-level fields are exactly `format`, `operation`, `status`, `data`, `error` as specified by H01. Dotted operation names distinguish preview and `.run`; dry-run uses the command operation and its existing result fields. Help/version/usage remain Clap text (syntax exit 2). Runtime errors/partial exit 1, successes exit 0. No debug chains or parser/native fragments are emitted by the new reporter; human failures use the same generated code/message. Legacy bare JSON success values and handled failure data are preserved.

For legacy commands, `data` is exactly the existing successful bare JSON result produced by the linked CLI modules; it is not a new saved-file schema. Required result fields/types are unchanged:

| Commands | Data contract / owning existing writer |
|---|---|
| Legacy `config.check` | `valid:bool`, `mode:string`, `encryption:bool`, `signing:bool`, `shape:string` ([entry point](../../crates/backupctl/src/main.rs)). |
| Versioned `config.check` | Exactly `valid:true`, `config_version:1`, `mode:"fixture"|"production"`, `access:"writer"|"reader"|"public"|"inventory"`, `read_only:bool`, `production_enabled:false`; no I/O certification. |
| `profile.list`, `profile.validate` | Profile array; validation object with profile, source major and resolved selection ([entry point](../../crates/backupctl/src/main.rs)). |
| Versioned inventory-role `key.status` | Exactly `keys:[]`; no resources opened. Other versioned key status/generate/publish capabilities remain unavailable. |
| Legacy `key.generate`, `key.publish`, `key.status` | Identity/recipient public status objects and optional signing status array; never seed bytes ([entry point](../../crates/backupctl/src/main.rs)). |
| `backup.create`, `backup.list`, `backup.inspect`, `backup.verify` | Existing development/signed result variants, or verification digests/level/origin/audit fact ([backup writer](../../crates/backupctl/src/backup.rs), [variant mappings](../../crates/backupctl/src/cli.rs)). |
| `backup.protect`, `backup.unprotect` | Backup UUID, protection string, changed/audit booleans ([backup writer](../../crates/backupctl/src/backup.rs)). |
| `backup.prune`, `backup.delete` | Existing exact preview sets/quota/scope and nullable plan/digest/expiry; `.run` retains operation/plan/digest/job UUID/outcome, disjoint completed/deleting/pending UUID arrays and audit boolean ([retention contract](m5b-retention.md)). |
| `restore.plan`, `restore.run` | Existing plan+digest or executed-plan/artifact/target/sections/security/verification/audit facts ([entry point](../../crates/backupctl/src/main.rs)); saved plan versions unchanged. |
| `job.*`, `inventory.*` | Existing safe job/integrity/discovery/adoption/rebuild/recovery objects ([inventory writer](../../crates/backupctl/src/inventory.rs), [inventory contract](m5a-inventory.md)). |

An error can carry an already computed diagnostic result without implying success. Only a known started incomplete destructive result marks `partial`; deletion retains its exact partition/job. Recovery retains its established result semantics; refused foreign working-directory names are reported warnings, not failed arbitrary deletions. Failures that return no structured service result have null data and no claim that the operation had zero effects; inspect durable jobs/recover before retrying. General structured native-job failure receipts remain a later H02 increment, before production enablement.

New boundary codes: `CONFIG_INVALID` (missing/unreadable/malformed/structurally invalid config), `CONFIG_VERSION_UNSUPPORTED` (integer version other than 1), `CREDENTIAL_UNSAFE` (unsafe versioned config file), `ACCESS_DENIED`, `READ_ONLY`, `PRODUCTION_NOT_ENABLED`, `OUTPUT_FORMAT_UNSUPPORTED`, `CAPABILITY_NOT_ENABLED` (specified but not yet implemented versioned operation). Existing named retention/older-snapshot codes and `INVENTORY_CORRUPT` are preserved through an explicit allowlist. Uncoded legacy busy/stale failures use `OPERATION_BUSY`/`PLAN_STALE`. Other legacy service failures become generated `NATIVE_OPERATION_FAILED` for native command classes, otherwise `OPERATION_FAILED`. An explicit static phrase catalogue preserves established fixture diagnostics without interpolated names, paths or causes. Messages are fixed safe text below 512 UTF-8 bytes; arbitrary underlying messages cannot become codes or output. No automatic retry advice is inferred from an error.

Acceptance: closed-schema and role/command cases, config file safety/no side effects, production gate for all command classes, source-independent keyless execution with missing keys/tools, legacy JSON/envelope equivalence, syntax/runtime exits and safe failures, actual deletion partial partition and all existing workspace/frozen-vector tests. This increment does not need native authentication matrices because it adds no new native path; later native/filesystem/snapshot work must run its own required all-major gates.
