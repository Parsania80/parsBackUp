# H02 true snapshot reads and external scratch contract

Recorded before implementation on 2026-11-16. This is a declarative fixture contract, not an operating flow. Production remains disabled. A snapshot is a quiescent copied store or read-only medium supplied by the operator; the application cannot certify that a live copy was made consistently. No new live-reader lock domain is introduced. Writable operations retain the existing activity/artifact/scope ownership.

## Capability and custody

Versioned `read_only=true` enables reader/public/inventory job list/inspect and inventory check/list/verification reads. Backup list is available to reader/public roles, signature verification to reader/public, and authenticated inspect/checksum/archive verification to reader only. Existing authorization/production/read-only refusals run first. Writer read-only configurations remain invalid. Writable authenticated offline backup commands remain gated for their own increment.

Backup discovery opens no keys, scratch, tools, source or passfile. Signature verification opens only the verifier, even for a reader with an unusable identity. Authenticated inspection/checksum opens identity and verifier, validates signature before manifest decryption and binds globals through the authenticated manifest. Archive verification additionally decrypts payload into external scratch, validates the source-major trusted root-owned ELF pg_restore and compares its offline TOC digest. It never connects to PostgreSQL. A configured source/passfile is ignored for all snapshot commands; no metadata probe of those resources or forbidden writer keys is performed. Inventory/job commands are key-free. Existing result shapes, rollback warnings and signature-level limitations remain: discovery is untrusted, and the signature authenticates the backup ID and ciphertext digests, not every discovery claim. `audit_recorded` is false wherever the established report contains it; list/inspect retain their established result shapes. No observation enrichment occurs, even if the command-level `--read-only` flag is omitted.

## Filesystem and bounded reads

Store ancestry and directory handles use the protected no-follow/nonblocking descriptor boundary. Snapshot root/artifacts and present private layout directories must be service-owned mode 0700 or stricter; files may be read-only (0400/0500 layouts work). No mkdir/chmod/migration/recovery/lock/plan/job/audit/artifact write is permitted in the snapshot. Root descriptor lifetime extends through all read handles. Root/service and same-UID mutation remain trusted; procfs is required. Renaming the configured root does not redirect held reads, but SQLite transaction continuity across a later root move is not promised.

The catalogue is capped at 4096 entries, each artifact at eight regular service-owned private single-link components. Canonical UUID directory names are required; unsupported names, symlinks, FIFOs, aliases and extra components refuse. Incomplete directories may be listed only as absent from completed discovery; authenticated selected reads require signed v1 layout and completion. Listing reports unsigned IDs without decrypting legacy metadata. Inventory discovery retains existing mixed-shape semantics under the same bounds. File inspection uses existing bounded public/signature/manifest readers and configured payload/globals ciphertext limits before streaming; fixed per-file bounds plus entry/component limits bound catalogue work. No arbitrarily growing directory is materialized before the entry cap.

An optional inventory is inspected as a private regular single-link file of at most 64 MiB; all SQLite `-journal`, `-wal`, `-shm` sidecars are refused, including empty files and symlinks. Database headers requiring WAL refuse before SQLite. An explicit immutable SQLite URI open avoids database read locks as well as sidecar creation. Current and supported historical schemas are read without migration. Views, triggers and virtual tables are refused before estate binding or application row queries. At most 32 user tables and 100000 aggregate rows are admitted before public row materialization; corruption/unsupported schema refuses. Missing inventory is allowed for artifact discovery/authentication but inventory/job commands report its absence. Inventory remains a local observation, not independent freshness or tamper evidence. A copied deleting/deleted row continues to prevent artifact consumption.

## External plaintext ownership

Authenticated commands require explicit `[scratch] root`; no `/tmp` fallback. The directory must already exist, service-owned mode 0700 or stricter with protected ancestry. Store, scratch and actual used key-parent trees must be disjoint by descriptor ancestry/device/inode, not merely lexical paths. These checks cover visible directory ancestry and inode identity; mount aliases that hide backing ancestry are outside this guarantee. Operators must provide disjoint backing trees. Unused source/passfile paths are not opened to prove broader mount isolation. Store/scratch are never recursively created or repaired. Scratch is not opened at all for keyless or signature-only reads.

Each decryption creates a UUID directory (0700) and file (0600) beneath the pinned external scratch descriptor. Only the operation's own directory is removed on normal success/error; pre-existing siblings are preserved and never swept. Existing payload/globals/manifest limits, aggregate live-view quota per handle and observed free-space reserve apply. No over-limit byte is written. Failed cleanup retains its quota charge until the owning handle ends. Process death can leave plaintext in external scratch; automatic startup sweeping, secure erasure and cross-process scratch quotas are not promised. Service containment/cancellation and an approved copy/cleanup operating procedure remain later H02/H04 work.

## Acceptance

Generated safe snapshot refusal codes accompany missing scratch, unsafe/nonquiescent resources and catalogue/inventory limits; no raw SQL/key/native output escapes. Existing production/role/result codes remain. Verify unchanged formats/vectors, all workspace checks, key-free and verifier-only positive controls, wrong-key/tamper refusal before plaintext/native execution, exact scratch cleanup/quota/reserve controls and descriptor aliases. Actual PG16/17/18 signed fixtures must pass offline signature/checksum/archive checks after source loss. Test non-root read-only media/bind mounts, before/after store hashes/metadata and syscall traces proving no store writes/locks/migrations, no source/passfile opens and no database/network connections. Preserve legacy native/key/signing regressions appropriate to shared reader changes. Full H02 and production acceptance are not implied.
