# H03 fixture package and systemd contract

Recorded before implementation on 2026-11-16 after H02 checkpoint `3cc9326`. This is a declarative contract, not an operating flow. Target environments are Debian 13 and Ubuntu 24.04 LTS, amd64. Production remains disabled; package installation cannot authorize real sources. No core/schema/cryptographic/plan change is planned.

## Package and custody

`deploy/build-deb.sh` packages a caller-supplied release ELF binary using dpkg-deb, derives shared-library dependencies with dpkg-shlibdeps and normalizes archive ownership/timestamps using SOURCE_DATE_EPOCH (default: source commit time). It never compiles against an unstated host runtime or bundles host libraries. Build the binary against the oldest supported runtime (Ubuntu 24.04); actually install/run the same package on both targets. This is repeatable packaging of supplied bytes, not a claim of independently reproducible Rust builds. Package version defaults to the crate version with a fixture prerelease suffix.

The package installs `/usr/bin/backupctl`, two systemd templates and an inert example under `/usr/share/doc/backupctl`. It generates no configuration, credential or key. Maintainer scripts create a static non-login `backupctl:backupctl` identity and protected directories: root-owned/group-backupctl `/etc/backupctl` and `profiles` (0750), service-owned `keys` and `credentials` (0700), and service-owned `/var/lib/backupctl` (0700). Config files under `profiles` must be service-owned 0600, as required by the existing parser. The store is `/var/lib/backupctl/store`; native clients remain independently installed matching-major trusted executables. Refuse incompatible existing identities, symlinks or directory ownership/modes; never recursively repair user data.

Install/reconfigure never starts/enables a timer or service. Upgrade reloads units and preserves existing enabled/active scheduling and in-flight jobs; no automatic backup/restart is issued. Removal stops loaded backup timers/services and disables known timer instances before removing units. Purge preserves administrator-created configs, credentials, keys, inventory, artifacts and the OS identity; destruction of recovery material is always explicit administrator work. Reinstall accepts preserved matching custody without rewriting existing material. Maintainer scripts are idempotent and work in a chroot without a running system manager.

## Invocation and schedule

`backupctl-backup@NAME.service` runs the same CLI directly as the service user, reading `/etc/backupctl/profiles/NAME.toml`, selecting profile NAME and json-v1 output. There is no shell, environment-file credential transport, alternate engine or additional lock. NAME is a configured simple profile name (letters/digits/underscore/hyphen); use systemd's literal `%i`, never unescaped `%I` in paths. The shipped invocation includes `--confirm-synthetic` and is intentionally fixture-only. Production release must separately review its invocation and compatibility gates.

The matching timer is opt-in: daily at 02:00 UTC with up to 15 minutes random delay, one-minute accuracy and Persistent=true. Missed calendar events coalesce into one catch-up activation. An already running instance is not restarted by its timer. Manual CLI invocations share existing nonblocking scope claims; a competing same-scope job refuses without publication. Different profiles retain existing core scope semantics. There is no automatic retry after an operation failure and no retention/restore scheduling.

## Sandbox and containment

The oneshot service uses UMask=0077, no capabilities, no new privileges, protected home/system/kernel/control groups, private devices/tmp, restricted namespaces/address families and a writable state directory only. Configuration/key/credential directories stay read-only to the service; bootstrap is an explicit separate administrator-controlled action as the service user outside the backup unit. Normal `/proc/self/fd` access remains available for the existing descriptor-based native/store paths. Local peer sockets and loopback SCRAM remain reachable; the application continues enforcing local endpoints.

TimeoutStartSec bounds the entire oneshot at two hours; per-tool limits remain. KillMode=mixed gives SIGTERM to the CLI for ordinary cleanup, then SIGKILL to every remaining service-cgroup process after a 30-second stop grace. This includes descendants that create another process group/session. No delegation is granted. A service hard stop cannot guarantee a final report or database rollback; inherited-claim recovery and interrupted jobs remain core behavior. Resource defaults (2 GiB memory, 128 tasks, 1024 file descriptors, no core dumps) are deployment limits, configurable by explicit administrator drop-ins for measured workloads. Sandbox controls are verified on actual target managers, not inferred from a security score.

## Acceptance and boundaries

Build/install/run the identical package in isolated Debian 13 and Ubuntu 24.04 systems with their own systemd PID1/cgroup namespace. Do not install host units, bind the host cgroup root writable or touch unrelated services. Verify install/reconfigure/reinstall/upgrade/remove/purge, no automatic activation, preserved custody/data, real service permissions/read-only paths, timer activation/manual overlap, native signed backup, source-loss restore with only recovery keys, SQLite migration and graceful/hard cancellation including an escaped-session child. Use matching distro PostgreSQL clients/server (Debian 17, Ubuntu 16) and independently inspect recovered data. H02's all-major native evidence remains historical for other combinations; this is package/service acceptance, not a new full content matrix.

## Observed compatibility gate

The initial Ubuntu 24.04/PG16.15 fixture selected `schemas=["public"]`. Its native dump emits `CREATE SCHEMA public`, which conflicts with the public schema already present in the fresh template0 target; the CLI safely leaves a partial target and reports failure. This is an existing core selective-restore compatibility issue, not fixed or certified by H03. The shipped example uses a full-database profile (`schemas=[]`, `large_objects=true`), and H03 must independently validate its restored row. V01 must resolve or explicitly exclude the observed selective-public case before production release. Do not interpret successful full-database package recovery as all selective-content acceptance.
